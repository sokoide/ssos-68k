# OS監査結果（2026-08-11）

性能、保守性、MC68000/X68000固有の安全性を分担して監査した。今回の実装は、ホスト/QEMU/クロスビルドで検証可能で、既存のハードウェア挙動を推測で変更しない範囲に限定した。

## 今回反映した改善

- ウィンドウ描画で参照されていなかった6KiBのz-mapと再構築処理を削除した。部分再描画は、重なるウィンドウをz昇順に再合成する現行方式へ文書と計測項目を統一した。
- ウィンドウIDの生存確認を一箇所へ集約し、破棄済みID、二重破棄、表現不能な座標・サイズ、NULL文字列を安全に拒否するようにした。
- buddy/slab allocatorでNULL、小さすぎるarena、サイズ加算overflow、過大alignment、不正なslab object size/countを安全に拒否するようにした。
- buddyのXOR再結合基準を管理領域込みのarena先頭から、実ブロック領域の先頭へ修正した。分割したブロックが64KiBまで再結合できず、空き容量があっても偽OOMになる問題を再現テストで固定した。
- 同一zのウィンドウでは後に作られたslotを最後に描画する順序へhit-testのtie-breakを合わせた。
- bare-metal起動時のMFP設定をIOCS呼び出し後の一度だけにした。これにより、BSS初期化前に独自ISRが動く競合と、保存した元ベクタ/MFP状態をBSS clearで失う問題を除去した。
- 通常ISRの`rte`直前に割り込みマスクを下げていた処理を削除した。`rte`が例外フレームのSRを復元するため、この処理は復帰直前の不要な多重割り込み窓になっていた。

## 保留した高リスク項目

以下は重要だが、X68000エミュレータまたは実機での計測・確認なしには変更しない。

1. `os/gfx/vram.c`のDMAC Ch.2設定は、BAR/BTCの転送情報テーブルを使う一方でOCRのchain指定とMAR/MTC設定に疑義がある。既存ベンチでは成功記録があるため、レジスタ値と転送先を実機で再確認する。根拠資料はx68k-masterの`resources/02_DMA.md`。
2. standaloneのTRAP #14異常終了経路は、通常終了時のMFP、COPY/NMIベクタ、画面、マウス復元を通らない。異常終了専用cleanupを設計し、意図的なbus/address error後にHuman68Kへ安全に戻れることを確認する。根拠資料は`resources/03_割り込み.md`と`resources/21_システム初期化と終了.md`。
3. V-DISP watchdogのMFP再設定値と排他方法に不整合がある。保存状態を上書きしない再設定APIへ分離して実機確認する。根拠資料は`resources/04_MFP.md`。
4. 256色2ページの`ss_gfx_flip()`はCRTC scroll register群の更新が不足している可能性がある。現在の未使用APIを安易に有効化せず、`resources/07_画面制御.md`に基づく実機テストを先に追加する。
5. `ss_disable_interrupts()` / `ss_enable_interrupts()`は元SRを保存しないため、ネストしたcritical sectionには使えない。ABIを決めた`ss_irq_save()` / `ss_irq_restore()`へ段階移行し、QEMUでSR保存復元を検証する。

## 次の検証順序

1. X68000エミュレータで大矩形DMA、timeout/fallback、転送先境界を計測する。
2. TRAP #14異常終了後にTimer D/V-DISP/COPY/NMIの全ベクタとHuman68K UI状態が復元されることを確認する。
3. mode 8 page flipのCRTC R12-R19を記録し、表示ページと描画ページを交互に検証する。
4. SR保存型critical-section APIをQEMUテストから導入する。
