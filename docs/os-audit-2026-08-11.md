# OS監査結果（2026-08-11）

本書は監査当時の記録であり、「保留した高リスク項目」は現在の未実装一覧ではない。後続の対応状況は[保守性・性能レビュー](maintenance-performance-review-2026-09-24.md)の末尾を参照する。

性能、保守性、MC68000/X68000 固有の安全性を分担して監査した。今回の実装は、ホスト/QEMU/クロスビルドで検証可能で、既存のハードウェア挙動を推測で変更しない範囲に限定した。

## 今回反映した改善

- ウィンドウ描画で参照されていなかった 6KiB の z-map と再構築処理を削除した。部分再描画は、重なるウィンドウを z 昇順に再合成する現行方式へ文書と計測項目を統一した。
- ウィンドウ ID の生存確認を一箇所へ集約し、破棄済み ID、二重破棄、表現不能な座標・サイズ、NULL 文字列を安全に拒否するようにした。
- buddy/slab allocator で NULL、小さすぎる arena、サイズ加算 overflow、過大 alignment、不正な slab object size/count を安全に拒否するようにした。
- buddy の XOR 再結合基準を管理領域込みの arena 先頭から、実ブロック領域の先頭へ修正した。分割したブロックが 64KiB まで再結合できず、空き容量があっても偽 OOM になる問題を再現テストで固定した。
- 同一 z のウィンドウでは後に作られた slot を最後に描画する順序へ hit-test の tie-break を合わせた。
- bare-metal 起動時の MFP 設定を IOCS 呼び出し後の一度だけにした。これにより、BSS 初期化前に独自 ISR が動く競合と、保存した元ベクタ/MFP 状態を BSS clear で失う問題を除去した。
- 通常 ISR の`rte`直前に割り込みマスクを下げていた処理を削除した。`rte`が例外フレームの SR を復元するため、この処理は復帰直前の不要な多重割り込み窓になっていた。

## 保留した高リスク項目

以下は重要だが、X68000 エミュレータまたは実機での計測・確認なしには変更しない。

1. `os/gfx/vram.c`の DMAC Ch.2 設定は、BAR/BTC の転送情報テーブルを使う一方で OCR の chain 指定と MAR/MTC 設定に疑義がある。既存ベンチでは成功記録があるため、レジスタ値と転送先を実機で再確認する。根拠資料は x68k-master の`resources/02_DMA.md`。
2. standalone の TRAP #14 異常終了経路は、通常終了時の MFP、COPY/NMI ベクタ、画面、マウス復元を通らない。異常終了専用 cleanup を設計し、意図的な bus/address error 後に Human68K へ安全に戻れることを確認する。根拠資料は`resources/03_割り込み.md`と`resources/21_システム初期化と終了.md`。
3. V-DISP watchdog の MFP 再設定値と排他方法に不整合がある。保存状態を上書きしない再設定 API へ分離して実機確認する。根拠資料は`resources/04_MFP.md`。
4. 256 色 2 ページの`ss_gfx_flip()`は CRTC scroll register 群の更新が不足している可能性がある。現在の未使用 API を安易に有効化せず、`resources/07_画面制御.md`に基づく実機テストを先に追加する。
5. `ss_disable_interrupts()` / `ss_enable_interrupts()`は元 SR を保存しないため、ネストした critical section には使えない。ABI を決めた`ss_irq_save()` / `ss_irq_restore()`へ段階移行し、QEMU で SR 保存復元を検証する。

## 次の検証順序

1. X68000 エミュレータで大矩形 DMA、timeout/fallback、転送先境界を計測する。
2. TRAP #14 異常終了後に Timer D/V-DISP/COPY/NMI の全ベクタと Human68K UI 状態が復元されることを確認する。
3. mode 8 page flip の CRTC R12-R19 を記録し、表示ページと描画ページを交互に検証する。
4. SR 保存型 critical-section API を QEMU テストから導入する。
